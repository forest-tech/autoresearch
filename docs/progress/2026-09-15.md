## NOTES

### worker ごとに戦略(prompts)を変える実験( `parallel-strategy-diversity` )

#### 設定

| worker | 戦略                     | 狙い                           |
| ------ | ---------------------- | ---------------------------- |
| 0      | Default / conservative | 現行探索を対照群として固定                |
| 1      | Random coordinate      | 多数のパラメータから1つをランダム寄りに選んで局所変更  |
| 2      | Sparse mutation        | GAの突然変異のように、ほとんどを維持し1〜2個だけ変異 |
| 3      | Adaptive mutation      | 履歴を見て未探索・停滞している方向を優先的に変異     |

#### 解説

`scripts/genkai/parallel_loop_for_codex.sh` と4つのプロンプトファイルに実装しました。

| Worker | 戦略 / `prompts/` 配下のテンプレート                  |
| ------ | ------------------------------------------ |
| 0      | コントロール — `candidate_default.txt`           |
| 1      | ランダム座標 — `candidate_random_coordinate.txt` |
| 2      | スパース変異 — `candidate_sparse_mutation.txt`   |
| 3      | 適応的変異 — `candidate_adaptive_mutation.txt`  |

シンプルなシェルの `case` 文で、各Workerのデフォルトテンプレートを選択するようにしています。明示的な上書き指定も引き続きサポートされ、その場合は `custom` としてログに記録されます。

起動時にはテンプレートの妥当性を検証し、Workerとテンプレートの対応関係を表示します。`NUM_WORKERS` のデフォルト値は4で、1〜4のみ指定可能です。

コントロール用プロンプトについては、その他のGit操作を行わないことを明示的に禁止する記述を追加しただけです。

検証はすべて成功しました。具体的には、Bashの構文チェック、空白チェック、既存の12件のテスト、およびテンプレートのパス／ハッシュ、履歴モード、目的関数を対象とした16件のレンダリングチェックを実施しています。さらに、Workerの割り当て、不正なWorker数、テンプレート欠損、共通制約についても確認済みです。

トレーニングは実行していません。トレーニング、評価、Git処理、勝者選択、履歴、スキーマ、成果物の配置については変更していません。

`experiment_utils.py`、`train.py`、`prepare.py` にも変更は加えていません。
