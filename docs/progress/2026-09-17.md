## NOTES

### SSH先（Linux）に [viu](https://github.com/atanunq/viu) をインストールする

#### 環境

- SSH先: Linux
- CPU Architecture: `x86_64`
- Terminal: WezTerm
- `viu`: v1.6.1

#### 1. インストール

`x86_64` のLinux環境なので、以下のバイナリを使用する。

`viu-x86_64-unknown-linux-musl`

```bash
mkdir -p ~/.local/bin

curl -L \
  -o ~/.local/bin/viu \
  https://github.com/atanunq/viu/releases/download/v1.6.1/viu-x86_64-unknown-linux-musl

chmod +x ~/.local/bin/viu
```

#### 2. 実行コマンド

```bash
viu <PNG＿FILE>
```

### worker ごとに戦略(prompts)を変える実験( `parallel-strategy-diversity` ) の結果について事実・戦略の狙いとの一致に述べる

2種類のグラフを作成した。

1. Workerごとのグラフ
  各Workerの評価指標の推移を個別に確認
  変更点、keep/discard、BPBの値を抽出
2. 全Workerを統合したグラフ
  4つのWorkerの結果を統合

#### Worker 0：Default / Conservative

| 観点 | 結果 |
| --- | --- |
| 狙い | 現在の良い設定を崩さず、堅実に改善 |
| keep | **3/9回** |
| 主な変更 | `TOTAL_BATCH_SIZE`, `MATRIX_LR`, `WARMDOWN_RATIO`, `ASPECT_RATIO` など |
| 改善 | keep値が **0.992355 → 0.991427 → 0.984280** と段階的に改善 |
| 悪化 | discard時も大きな悪化はほぼなし |
| 評価 | **狙い通り。4 Workerで最も安定した探索** |


#### Worker 1：Random Coordinate

| 観点 | 結果 |
| --- | --- |
| 狙い | ランダム寄りに変更対象を選び、局所解からの脱出・一度の大きな改善を狙う |
| keep | **2/9回** |
| 主な変更 | `SCALAR_LR`, `ASPECT_RATIO`, `ADAM_BETAS`, `FINAL_LR_FRAC` など幅広い |
| 改善 | `ASPECT_RATIO`変更で **0.992544 → 0.984518** と一気に改善 |
| 悪化 | **1.019690** まで悪化するなど、変動が大きい |
| 評価 | **狙い通り。安定性は低いが、大きな改善が発生** |


#### Worker 2：Sparse Mutation

| 観点 | 結果 |
| --- | --- |
| 狙い | 1〜2個だけ突然変異的に変更し、現在とは異なる解を探索 |
| keep | **0/9回** |
| 主な変更 | `WEIGHT_DECAY`, `EMBEDDING_LR`, `WARMUP_RATIO`, `SCALAR_LR` など |
| 改善 | 一部でまとまった改善があり、最良で **0.985711** |
| 悪化 | 改善・悪化を繰り返し、安定した更新にはつながらず |
| 評価 | **探索方法は狙い通り。ただし今回はkeepにつながる解を発見できず** |


#### Worker 3：Adaptive Mutation

| 観点 | 結果 |
| --- | --- |
| 狙い | 履歴を基に、未探索・停滞している方向を優先して探索 |
| keep | **1/9回** |
| 主な変更 | `WINDOW_PATTERN`, `HEAD_DIM`, `DEPTH` など構造的パラメータも探索 |
| 改善 | `DEPTH`変更などで大きく改善し、最終的に **0.984784** まで到達 |
| 悪化 | 大半がdiscardで、0.006〜0.007程度の大きな悪化も発生 |
| 評価 | **狙い通り。他Workerが触れていない方向まで探索できている** |


#### 全体

- **Worker 0**：段階的に改善し、大きな悪化も少ない → Conservativeの狙い通り
- **Worker 1**：大幅な悪化もあるが、一度に大きく改善 → Random探索の狙い通り
- **Worker 2**：keepはないが、少数パラメータを変異させる探索を実行 → Sparse mutationとしては狙い通り
- **Worker 3**：大半がdiscardだが、未探索の構造的パラメータまで探索 → Adaptive mutationの狙い通り

→ **探索の安定性は Worker 0 が最も高く、それ以外のWorkerでは意図的に探索性を高めたことで、性能変動やdiscardが増えている。各プロンプトで設定した探索戦略の違いが、実際の探索挙動にも現れている。**
