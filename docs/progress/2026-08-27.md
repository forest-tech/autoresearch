## 実験日報

### 概要

LLM事前学習の自動実験を3回実行した。各実験は5分間の固定学習時間で実施し、検証指標 `val_bpb`（低いほど良い）を比較した。

全3回とも学習は正常に完了した。

### 実験結果

| Iteration | 主な設定 | val_bpb | 備考 |
|---:|---|---:|---|
| 1 | `WARMDOWN_RATIO=0.50` | **0.996518** | 今回の最良値 |
| 2 | `WARMDOWN_RATIO=0.35` | 0.997396 | 最良値より悪化 |
| 3 | `WARMDOWN_RATIO=0.60`、Muon momentum ramp・weight decay scheduleを使用 | 0.996549 | Iteration 1とほぼ同等だが、わずかに悪化 |

### 学習条件・リソース

- モデル規模: 約5,033万パラメータ
- モデル構成: 8層、埋め込み次元512、語彙数8,192
- 学習時間: 各回約300秒
- 学習ステップ数: 934〜935 step
- 処理トークン数: 約4.9億トークン
- 最大VRAM使用量: 約45 GB
- MFU: 約39%

### 所見

- 最良の結果は Iteration 1 の `val_bpb=0.996518`。
- `WARMDOWN_RATIO` を0.50から0.35へ短縮すると、`val_bpb` が0.997396まで悪化した。
- 0.60では0.996549となり、0.50に近い性能へ戻ったが、最良値には届かなかった。
- したがって、今回の範囲では warmdown 比率は **0.50付近が有望**と考えられる。
- Iteration 1と3の差は `0.000031` と非常に小さく、再実行時のばらつきも確認する価値がある。

### 次回方針

- 次回は未試行の `WARMDOWN_RATIO=0.55` を設定済み。
- 0.50付近を細かく探索し、最良値の再現性を確認する。
- 学習速度・VRAM使用量は各実験でほぼ一定のため、当面はモデル規模を変えず最適化パラメータを中心に調整する。

## Codex の sandbox 設定

### やったこと
Singularity 内で Codex を `workspace-write` で実行したところ、以下の mount エラーが発生した。

```sh
bwrap: Can't bind mount /oldroot/ on /newroot/
```

### 結果

workspace-write では Codex が bwrap で追加の sandbox を作成するため、Singularity の bind mount と競合してファイル操作に失敗した。

danger-full-access では Codex 側の追加 sandbox を使わないため、この問題を回避できる可能性がある。

### 結論

Codex の隔離は Singularity 側で行い、Codex は --sandbox danger-full-access で実行する方針とした。

## `--bind` と Codex のアクセス範囲

`--bind ${WORKDIR}:${WORKDIR}` は、Codex を `WORKDIR` 内に閉じ込める設定ではなく、`WORKDIR` をコンテナ内に追加でマウントする設定。

Singularity では `$HOME` や `/tmp` などがデフォルトで見える場合があるため、`danger-full-access` を使うと `WORKDIR` 外も操作できる可能性がある。

そのため、Codex をより安全に隔離するには、Singularity 側で `--contain` / `--containall` などを利用して、見えるディレクトリを制限する必要がある。
